Problem Statement

Why AV block detection is a hard problem and what makes it clinically critical.

What Are AV Blocks?

Atrioventricular (AV) blocks are electrical conduction abnormalities in the cardiac conduction system. Under normal sinus rhythm, every P-wave (atrial depolarisation) is followed by a QRS complex (ventricular contraction) after a fixed PR interval of 120–200 ms. AV blocks disrupt this coupling in different ways depending on severity.

DegreeWhat HappensPR IntervalP:QRS RatioSeverity
NormalEvery P followed by QRS, fixed PR120–200 ms1:1Normal
1st DegreeAll P-waves conducted, but PR is prolonged>200 ms (fixed)1:1Mild
2nd Degree Mobitz IPR progressively lengthens until a QRS is dropped (Wenckebach)Progressive>1:1Moderate
2nd Degree Mobitz IISudden dropped QRS with no PR warningFixed, then dropped>1:1Severe
3rd Degree (Complete)Full dissociation — atria and ventricles beat independentlyNo association>1.9:1Critical

The Technical Challenges

1. P-wave Detection is Hard

P-waves are the most difficult waveform to detect automatically in ECG:

  • Low amplitude — typically 0.1–0.2 mV, one-tenth of QRS amplitude (~1–2 mV)
  • Morphological variability — shape changes between patients and AV block types
  • Overlap risk — in fast rhythms, P-waves can overlap with the preceding T-wave
  • Buried in noise — powerline interference (50/60 Hz) and baseline wander mask small P-waves
  • Dissociation — in 3rd Degree block, P-waves are unrelated to QRS and can appear anywhere including within the QRS or T-wave

2. PR Interval Precision Required

At 500 Hz, 1 sample = 2 ms. A PR interval of 200 ms = 100 samples. A 10-sample error is a 20 ms diagnostic error — enough to misclassify a borderline 1st Degree block. The model must localise P-wave boundaries accurately.

3. Existing Systems Are Inadequate

  • Hospital ECG machines use threshold-based algorithms designed in the 1980s — they output "abnormal ECG" without wave-level detail
  • Most deep learning ECG research targets AF or STEMI — AV block classification with wave segmentation is underexplored
  • XAI in ECG papers is usually post-hoc (GradCAM applied after training) — AtrionNet trains the heatmap head directly
  • No existing open-source system combines P-wave detection + PR interval measurement + AV block classification + explainability in one pipeline
⚠️ Research Disclaimer

AtrionNet is a research system. It has not been clinically validated or approved for diagnostic use. Do not use it as a substitute for clinical ECG interpretation.

AttentionalInception Block

The core building block of both encoder and decoder — multi-scale feature extraction with attention gating.

Each encoder and decoder level uses an AttentionalInception block. It's an Inception module modified with a Squeeze-and-Excitation attention gate and a residual connection.

Source Code

pythonsrc/modeling/atrion_net.py
class AttentionalInception(nn.Module):
    """Inception block with integrated Self-Attention to focus on weak P-waves."""
    def __init__(self, in_channels, out_channels):
        super(AttentionalInception, self).__init__()
        self.bottleneck = nn.Conv1d(in_channels, out_channels // 4, kernel_size=1)

        # Multi-scale convolutions
        self.conv_small  = nn.Conv1d(out_channels // 4, out_channels // 4, kernel_size=9,  padding=4)
        self.conv_medium = nn.Conv1d(out_channels // 4, out_channels // 4, kernel_size=19, padding=9)
        self.conv_large  = nn.Conv1d(out_channels // 4, out_channels // 4, kernel_size=39, padding=19)
        self.residual    = nn.Conv1d(in_channels, out_channels // 4, kernel_size=1)

        self.attention = AttentionBlock1D(out_channels)
        self.bn  = nn.BatchNorm1d(out_channels)
        self.relu = nn.ReLU()

    def forward(self, x):
        res    = self.residual(x)
        x_btn  = self.bottleneck(x)
        out1   = self.conv_small(x_btn)
        out2   = self.conv_medium(x_btn)
        out3   = self.conv_large(x_btn)
        out    = torch.cat([out1, out2, out3, res], dim=1)
        out    = self.attention(out)
        return self.relu(self.bn(out))

Squeeze-and-Excitation Attention

Channel-wise attention that weights ECG frequency bands relevant to P-wave detection.

The AttentionBlock1D is a 1D adaptation of the Squeeze-and-Excitation (SE) block. It learns to up-weight channels that contain P-wave frequency content (0.5–15 Hz) and suppress channels dominated by QRS energy (5–40 Hz).

How It Works

1

Squeeze

Global average pooling across the sequence length: (B, C, L) → (B, C). Produces a single descriptor per channel.

2

Excitation

Two-layer FC network: C → C//16 → C with ReLU + Sigmoid. Produces per-channel attention weights in [0,1].

3

Scale

Element-wise multiplication of input feature map by attention weights: boosts informative channels, suppresses noise channels.

pythonsrc/modeling/atrion_net.py
class AttentionBlock1D(nn.Module):
    """Squeeze-and-Excitation variant for 1D ECG signals."""
    def __init__(self, channels, reduction=16):
        super(AttentionBlock1D, self).__init__()
        self.avg_pool = nn.AdaptiveAvgPool1d(1)
        self.fc = nn.Sequential(
            nn.Linear(channels, channels // reduction, bias=False),
            nn.ReLU(inplace=True),
            nn.Linear(channels // reduction, channels, bias=False),
            nn.Sigmoid()
        )

    def forward(self, x):
        b, c, _ = x.size()
        y = self.avg_pool(x).view(b, c)      # Squeeze
        y = self.fc(y).view(b, c, 1)         # Excitation
        return x * y.expand_as(x)            # Scale

Dilated CNN Bridge

Why the BiLSTM was replaced and how dilated convolutions solve the problem.

⚠️ Why Not BiLSTM?

Early versions (v1–v4) of AtrionNet used a Bidirectional LSTM at the bottleneck. With a 625-step sequence after three pooling layers, the BiLSTM suffered severe vanishing gradient issues. Training would converge initially then collapse — the model predicted zero P-waves after ~30 epochs. The Dilated CNN Bridge was the architectural solution.

Dilated Convolutions

A dilated convolution (also called atrous convolution) inserts gaps between filter weights, exponentially expanding the receptive field without increasing the number of parameters or reducing resolution.

LayerChannelsDilationReceptive FieldCoverage @ Input
Bridge 1256 → 51213 samples24 ms
Bridge 2512 → 51225 samples40 ms
Bridge 3512 → 51249 samples72 ms
Combined——9 samples @ bottleneck~720 ms @ input
✅ Result

720 ms effective receptive field at the input level — sufficient to model inter-P-wave timing, which is physiologically 300–800 ms in AV block cases. No recurrence = no vanishing gradients.

# Bridge: Dilated Convolutional Context (Solves BiLSTM Vanishing Gradients)

Decoder + Skip Connections

Reconstructing full-resolution segmentation maps from the compressed bridge representation.

The decoder mirrors the encoder. At each level, ConvTranspose1d upsamples by ×2, then concatenates the matching encoder skip connection before passing through an AttentionalInception block. Dropout (p=0.2) is applied after each decoder block during training.

Why Skip Connections Matter Here

The encoder compresses the 5000-sample sequence to 625 samples at the bottleneck. Fine-grained P-wave boundary information (onset/offset at sample precision) is lost at deep levels. Skip connections carry this high-resolution spatial detail from the encoder directly to the corresponding decoder level, allowing the model to reconstruct precise wave boundaries rather than just coarse locations.

pythonsrc/modeling/atrion_net.py — forward()
def forward(self, x):
    # Encoder
    e1 = self.enc1(x)
    e2 = self.enc2(self.pool1(self.drop_e1(e1)))
    e3 = self.enc3(self.pool2(self.drop_e2(e2)))

    # Bridge
    b = self.pool3(self.drop_e3(e3))
    b = self.bridge_relu(self.bridge_bn1(self.bridge1(b)))
    b = self.bridge_relu(self.bridge_bn2(self.bridge2(b)))
    b = self.bridge_relu(self.bridge_bn3(self.bridge3(b)))
    b = self.drop_b(b)

    # Decoder with skip connections
    d3 = self.drop_d3(self.dec3(torch.cat([self.up3(b), e3], dim=1)))
    d2 = self.drop_d2(self.dec2(torch.cat([self.up2(d3), e2], dim=1)))
    d1 = self.dec1(torch.cat([self.up1(d2), e1], dim=1))

    return {
        'heatmap': self.heatmap_head(d1),
        'width':   self.width_head(d1),
        'mask':    self.mask_head(d1)
    }

Three parallel prediction heads — each producing a (1, 5000) output from the 64-channel decoder feature map.

Heatmap Target Generation

During training, the heatmap target is a Gaussian distribution centered on each P-wave peak:

python
# Gaussian heatmap target (sigma=6 samples = 12ms at 500Hz)
sigma = 6
for onset, peak, offset in p_waves:
    center = peak
    for i in range(max(0, center - 3*sigma), min(5000, center + 3*sigma)):
        heatmap[i] = max(heatmap[i],
                         np.exp(-((i - center)**2) / (2 * sigma**2)))
ℹ️ Why σ=6?

σ=6 samples = 12 ms at 500 Hz. This creates a tight Gaussian that rewards the model for precise peak localisation while still providing a gradient surface around the true peak. At σ=6 the target exceeds 0.8 (the Focal Loss positive threshold) only within ±8 samples (~16 ms) of the true peak.

AtrionNetBaseline

Simple U-Net without attention or dilated bridge — used for ablation studies.

The baseline model uses standard Conv-BatchNorm-ReLU blocks at each level instead of AttentionalInception. It has no SE attention and no dilated bridge — the bottleneck is a plain enc3 block. Same three output heads and same loss function.

Purpose: quantify the contribution of the Attentional Inception encoder and the Dilated CNN Bridge by comparing performance against the hybrid model under identical training conditions.

pythonsrc/modeling/atrion_net.py
class AtrionNetBaseline(nn.Module):
    """Competitive U-Net Baseline for fair ablation study."""
    def __init__(self, in_channels=12):
        super(AtrionNetBaseline, self).__init__()
        def cbr(in_c, out_c):
            return nn.Sequential(
                nn.Conv1d(in_c, out_c, 3, padding=1),
                nn.BatchNorm1d(out_c),
                nn.ReLU()
            )
        self.enc1  = cbr(in_channels, 64)
        self.pool1 = nn.MaxPool1d(2)
        self.enc2  = cbr(64, 128)
        self.pool2 = nn.MaxPool1d(2)
        self.enc3  = cbr(128, 256)

        self.up2   = nn.ConvTranspose1d(256, 128, 2, 2)
        self.dec2  = cbr(256, 128)
        self.up1   = nn.ConvTranspose1d(128, 64, 2, 2)
        self.dec1  = cbr(128, 64)

        self.h = nn.Sequential(nn.Conv1d(64, 1, 1), nn.Sigmoid())
        self.w = nn.Conv1d(64, 1, 1)
        self.m = nn.Sequential(nn.Conv1d(64, 1, 1), nn.Sigmoid())

What's in LUDB

LUDB contains 200 12-lead ECGs from 200 patients, each 10 seconds at 500 Hz. Each ECG is annotated by expert cardiologists at the individual wave level for multiple leads:

  • P-wave: onset, peak, offset positions (in samples)
  • QRS complex: onset, peak, offset
  • T-wave: onset, peak, offset

The dataset covers a range of rhythm types including normal sinus rhythm, various AV block degrees, bundle branch blocks, right/left axis deviation, and hypertrophy patterns.

Annotation Format

Files are in WFDB format. For each record N, there is:

  • N.hea — header file with metadata (leads, sampling rate, gain)
  • N.dat — binary signal data
  • N.ii, N.v1, N.v5, etc. — per-lead annotation files

AtrionNet reads from Lead II annotations first (.ii), falling back through v1, v5, i, iii, avf if Lead II has no annotations.

Annotation Parsing Logic

The P-wave annotation symbols are stored as triplets: ( (onset), p (peak), ) (offset). The loader scans the annotation sequence and extracts each (p) triplet:

pythonsrc/data_pipeline/ludb_loader.py
i = 0
while i < len(ann.sample):
    if ann.symbol[i] == '(' and i+2 < len(ann.sample):
        if ann.symbol[i+1] == 'p' and ann.symbol[i+2] == ')':
            onset  = ann.sample[i]
            peak   = ann.sample[i+1]
            offset = ann.sample[i+2]
            if offset < self.target_length:   # 5000 samples
                p_waves.append((onset, peak, offset))
            i += 3
        else:
            i += 1
    else:
        i += 1

Record Discovery

The loader recursively scans the data directory for .hea files using Path.rglob(). It stores a mapping of record stem → parent directory to correctly handle nested folder structures in the LUDB release. Files in .ipynb_checkpoints are automatically excluded.

Signal Normalisation

Records are cropped or zero-padded to exactly 5000 samples:

  • If signal.shape[1] > 5000: crop to first 5000 samples
  • If signal.shape[1] < 5000: zero-pad on the right

The resulting shape is always (12, 5000) — 12 leads, 5000 samples.

Powerline Noise Synthesis

The powerline noise function synthesizes realistic mains interference using cosine harmonics with random phase and amplitude per harmonic:

python
def _tnoise_powerline(fs=500, N=5000, C=1.0, fn=50.0, K=3):
    t = torch.arange(0, N/fs, 1./fs)
    signal = torch.zeros(N)
    phi1 = random.uniform(0, 2*math.pi)
    for k in range(1, K+1):
        ak = random.uniform(0, 1)
        signal += C * ak * torch.cos(2*math.pi * k * fn * t + phi1)
    return signal * 0.05   # Scale to realistic ECG amplitude

Loss Functions

Multi-task loss combining Focal Loss for detection, Smooth L1 for width regression, and weighted BCE + Dice for segmentation.

Combined Instance Loss

The total training loss is a weighted sum across all three output heads:

diagram
Total Loss = (2.0 × Heatmap Focal Loss)
           + (1.0 × Width Smooth L1)
           + (1.0 × Mask BCE + Dice)

Focal Loss (Heatmap Head)

The focal loss is adapted for Gaussian heatmap targets. Pixels with target ≥ 0.8 are treated as positives (the core of the P-wave Gaussian), allowing gradient flow from the blurred edges:

pythonsrc/losses/segmentation_losses.py
def focal_loss(pred, target, alpha=2.0, beta=4.0):
    pred = torch.clamp(pred, 1e-6, 1 - 1e-6)
    pos_inds    = target.ge(0.8).float()   # Positives: heatmap >= 0.8
    neg_inds    = target.lt(0.8).float()   # Negatives: everything else
    neg_weights = torch.pow(1 - target, beta)   # Downweight near-positives

    pos_loss = torch.log(pred) * torch.pow(1 - pred, alpha) * pos_inds
    neg_loss = torch.log(1 - pred) * torch.pow(pred, alpha) * neg_weights * neg_inds

    num_pos = pos_inds.float().sum()
    if num_pos == 0:
        return -neg_loss.mean()
    return -(pos_loss.sum() + neg_loss.sum()) / (num_pos + 1e-6)

Width Loss (Smooth L1)

Only computed at positive locations (mask > 0.5). Uses Smooth L1 (Huber loss) which is less sensitive to large width prediction errors than MSE, important when the model is learning at early epochs.

Mask Loss (Weighted BCE + Dice)

The mask target is a binary map. P-waves occupy ~5-10% of the signal — a severe class imbalance. A positive weight of 5.0 is applied in BCE to compensate. Dice loss further improves overlap-based performance:

python
pos_weight = torch.tensor([5.0], device=pred['mask'].device)
m_bce  = F.binary_cross_entropy_with_logits(
    pred['mask'], target['mask'], pos_weight=pos_weight
)
m_loss = m_bce + dice_loss(torch.sigmoid(pred['mask']), target['mask'])

2

Per-Epoch Training Pass

For each batch: forward pass → compute combined loss → backward → gradient clip (max norm 1.0) → Adam step. Augmentations applied on-the-fly during training.

3

Validation + Metric Computation

Run inference on validation set. Decode heatmap peaks with NMS → compute Precision, Recall, F1, mAP. Scheduler steps on validation F1.

4

Early Stopping + Checkpoint Save

If validation F1 improves: save atrion_hybrid_best.pth. If no improvement for 25 epochs: stop training.

5

Plot Training Curves

Loss, Precision, Recall, and F1 curves saved to outputs/plots/ at the end of training.

⏱️ Training Time

~2–4 hours on an RTX 3060 for 150 epochs on the full LUDB dataset (200 records). CPU training is possible but significantly slower (~15–20× longer).

Signal Processing

Bandpass filtering and wave detection pipeline used in inference.

Preprocessing Filter

A 2nd-order zero-phase Butterworth bandpass filter is applied to the signal before each wave detection step:

WaveFilter BandPurpose
QRS (R-peak)5–40 HzEmphasizes QRS high-frequency components, suppresses P/T
P-wave0.5–15 HzPasses P-wave energy, removes QRS high-frequency content
T-wave0.5–15 HzSame as P-wave band for T-wave detection window

QRS Detection

python
def _detect_qrs(signal, fs=500):
    ecg    = _bandpass(signal, lo=5.0, hi=40.0)
    ecg_sq = np.abs(ecg) ** 2                   # Energy envelope
    min_dist = int(0.4 * fs)                     # 400ms refractory period
    peaks, _ = find_peaks(ecg_sq,
                           distance=min_dist,
                           height=np.percentile(ecg_sq, 75))  # Top 25% energy
    return peaks.tolist()

P-wave Detection (Fallback Mode)

python
def _detect_p_waves(signal, r_peaks, fs=500):
    ecg = _bandpass(signal, lo=0.5, hi=15.0)
    pr_window = int(0.30 * fs)   # Search 300ms before each R-peak
    p_half_w  = int(0.05 * fs)   # ±50ms around P peak = 100ms span

    for r in r_peaks:
        start = max(0, r - pr_window)
        end   = max(0, r - int(0.04 * fs))   # Don't overlap with QRS onset
        region = ecg[start:end]
        local_peaks, _ = find_peaks(region, prominence=0.02)
        if local_peaks.size > 0:
            best  = local_peaks[np.argmax(region[local_peaks])]
            p_idx = start + best
            spans.append((int(max(0, p_idx - p_half_w)),
                          int(min(len(signal)-1, p_idx + p_half_w))))

Interval Computation

python
def _compute_intervals(r_peaks, p_spans, fs=500):
    rr = [r_peaks[i+1] - r_peaks[i] for i in range(len(r_peaks)-1)]
    pr = []
    for p_onset, p_offset in p_spans:
        p_center   = (p_onset + p_offset) // 2
        candidates = [r for r in r_peaks if r > p_center]   # Next R after P
        if candidates:
            pr.append(int(candidates[0] - p_center))
    p_qrs_ratio = round(len(p_spans) / max(1, len(r_peaks)), 2)
    return {"pr": pr, "rr": rr, "p_qrs_ratio": p_qrs_ratio}

AV Block Classification

Rule-based classifier that maps measured intervals to a clinical diagnosis.

After the model detects P and QRS waves and measures intervals, a deterministic rule-based classifier maps the findings to a diagnosis. The primary discriminator is the P:QRS ratio — the ratio of detected P-waves to detected QRS complexes.

Classification Rules

p_qrs_ratio > 1.9 → 3rd Degree AV Block (Complete) Severe
More than 1.9 P-waves per QRS indicates full atrial-ventricular dissociation. The atria and ventricles beat at entirely different rates.
p_qrs_ratio > 1.4 → 2nd Degree AV Block (Mobitz II) Severe
Ratio between 1.4–1.9 indicates some P-waves are blocked (not followed by QRS), without progressive PR changes.
p_qrs_ratio > 1.15 AND PR progressively lengthens → 2nd Degree Mobitz I (Wenckebach) Moderate
Progressive PR prolongation detected: at least one consecutive PR interval increase of >20ms. Classic Wenckebach pattern.
avg_pr_ms > 200 → 1st Degree AV Block Mild
All P-waves conduct (ratio ≈ 1.0) but PR interval consistently exceeds 200ms. Benign in most patients.
Otherwise → Normal Sinus Rhythm Normal
P:QRS ≈ 1.0 and PR 120–200ms. Normal conduction.

Confidence Scoring

The confidence score is derived from the model's own heatmap — not a softmax output. It takes the mean of the maximum heatmap value within each detected P-wave span:

python
if heatmap is not None and p_spans:
    peak_scores = []
    for s, e in p_spans:
        if s < e and e <= len(heatmap):
            peak_scores.append(np.max(heatmap[s:e+1]))
    if peak_scores:
        confidence = float(np.mean(peak_scores))
ℹ️ Why This Confidence Measure?

A confidence score derived from the model's own detection probability is more informative than a class-level softmax score. It directly reflects how certain the neural network was about the P-wave detections that drove the diagnosis — not just which class was selected at the output.

Explainability (XAI)

Built-in heatmap explainability and the clinical importance map.

Primary XAI: Heatmap Head

The heatmap output of the model is itself the primary XAI artifact. Unlike post-hoc methods (GradCAM applied after training), the heatmap head is trained end-to-end with focal loss against Gaussian P-wave targets. This means the model explicitly learns to produce high confidence values where P-waves are — the heatmap is interpretable by design.

Clinical Importance Map

Beyond the raw heatmap, a structured clinical importance map is computed in _build_importance_map(). It combines all detected wave types with physiologically motivated importance weights:

Wave TypeBase ImportanceIn AV Block
QRS Complex0.95High — ventricular response marker
P-wave (in AV block)0.95Maximum — the discriminating feature
P-wave (normal)0.80Reduced — less clinically critical
T-wave0.70Low — repolarisation context

Confidence-Adaptive Spreading

The sigma of each Gaussian importance peak scales with confidence. High-confidence detections produce sharp, focused peaks; low-confidence detections produce wider, more uncertain regions:

python
conf = diagnosis.get("confidence", 0.85)
# High confidence → tight peaks; low → wide/dispersed
sigma_scale = 1.0 + (1.0 - conf) * 2.0

# For each wave span, compute Gaussian importance:
center = (start + end) // 2
sigma  = max(1, (wave_width / 2.0) * sigma_scale)
peak   = importance_base * np.exp(-((x - center)**2) / (2 * sigma**2))

Evaluation Metrics

Instance-level detection metrics following AAMI/CSE clinical ECG evaluation standards.

Performance is measured at the P-wave instance level, not the ECG record level. Each predicted P-wave span is matched against the ground truth annotations from LUDB.

True Positive Criterion

A predicted P-wave is counted as a True Positive if its center falls within the annotated onset-to-offset span of a ground truth P-wave, with ±10 sample (20 ms) slack:

python
slack = 10  # 20ms slack at 500Hz (AAMI/CSE standard)
if (t_start - slack) <= pred['center'] <= (t_end + slack):
    # True Positive

Metric Definitions

MetricFormulaMeaning
PrecisionTP / (TP + FP)Of all predicted P-waves, what fraction are correct?

F1-Score2 × P × R / (P + R)Harmonic mean of Precision and Recall

mAP Computation

mAP is computed using VOC 2010+ style area-under-curve interpolation:

pythonsrc/engine/atrion_evaluator.py
def calculate_mAP(all_tp_lists, all_scores, total_gt):
    flat_tp     = np.concatenate(all_tp_lists)
    flat_scores = np.concatenate(all_scores)
    order       = np.argsort(flat_scores)[::-1]
    tp_sorted   = flat_tp[order]
    tp_cumsum   = np.cumsum(tp_sorted)
    fp_cumsum   = np.cumsum(1 - tp_sorted)
    recalls     = tp_cumsum / total_gt
    precisions  = tp_cumsum / (tp_cumsum + fp_cumsum)

    # All-point interpolation (VOC 2010+)
    m_rec = np.concatenate(([0.], recalls, [1.]))
    m_pre = np.concatenate(([0.], precisions, [0.]))
    for i in range(len(m_pre) - 2, -1, -1):
        m_pre[i] = max(m_pre[i], m_pre[i + 1])
    idx = np.where(m_rec[1:] != m_rec[:-1])[0]
    ap  = float(np.sum((m_rec[idx+1] - m_rec[idx]) * m_pre[idx+1]))
    return ap, recalls, precisions

1D NMS & Threshold Calibration

Non-Maximum Suppression and the iterative process of calibrating detection thresholds.

1D Non-Maximum Suppression

After peak detection, overlapping predictions (IoU > 0.5) are suppressed, keeping the highest-confidence detection. This prevents double-counting of P-waves that are detected by multiple peaks in the same region.

python
def _nms_1d(instances, iou_threshold=0.5):
    instances = sorted(instances, key=lambda x: x['confidence'], reverse=True)
    keep = []
    suppressed = set()
    for i, inst_a in enumerate(instances):
        if i in suppressed:
            continue
        keep.append(inst_a)
        for j, inst_b in enumerate(instances[i+1:], start=i+1):
            if j in suppressed:
                continue
            iou = calculate_1d_iou(inst_a['span'], inst_b['span'])
            if iou > iou_threshold:
                suppressed.add(j)
    return keep

Threshold Calibration History

VersionConf. ThresholdMin DistancePrecisionRecallResult
v4.00.2020 samples0.04High5167 false positives — T-waves misdetected as P-waves
v4.10.50100 samplesHigh0.31152 missed P-waves — threshold too strict for weak dissociated P-waves
v4.20.3560 samples——Balanced target F1 ≥ 0.70
Final0.4560 samples——Tuned to σ=6 Gaussian targets. Excludes T-waves (0.1–0.2) while capturing weak P-waves

Physiological Justification

  • conf=0.45: P-waves in AV block can be partially buried in noise; 0.45 captures weak but genuine dissociated P-waves while excluding T-waves and noise (typically score 0.1–0.25)
  • distance=60 samples: 120 ms minimum inter-P-wave gap. The fastest pathological atrial rate in AV block is ~180 bpm = 333 ms cycle, so 120 ms is a safe physiological floor
  • prominence=0.10: Peak must rise at least 10% above local surrounding — filters flat noise plateaux
